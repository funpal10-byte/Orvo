# Orvo — Original Voice Audit (mobile app)

A guided brand-audit app for ORVO Co. (Orvo Consulting LLP). A user answers 18
questions across six brand dimensions, gets a score benchmarked against a
peer set in their category, and a prioritised action list mapping each gap to
an ORVO Co. service suite.

Built in React Native + Expo, recreating the 8-screen design handoff
(`Original Voice Audit — mobile app`, PlatformOne™ Product 01) pixel-faithful
within platform conventions.

## Stack

- **Expo (React Native, TypeScript)** — cross-platform iOS/Android from one
  codebase, matching the handoff's recommendation for a form-driven,
  data-light app.
- **React Navigation** (native-stack) for the welcome → setup → assessment →
  scoring → results → gaps → report flow, with tab-style jumps between
  home/audit/results/actions.
- **Zustand + AsyncStorage** for local, offline-safe audit state (persists
  answers as you go, per the handoff's state-management spec).
- **react-native-svg** for the score ring, **expo-linear-gradient** for the
  gold gradient fill/buttons, **@expo-google-fonts** (Outfit, Manrope,
  JetBrains Mono) bundled with the app.
- **Supabase** (Postgres + auth) for the real backend — scoring, peer
  benchmarks and audit storage. See `supabase/README.md`.

## Structure

```
App.tsx                     entry point, font loading, navigation container, anon sign-in
src/
  screens/                  the 8 screens + the legal/about screen
  components/                shared UI: buttons, score ring, tab bar, etc.
  navigation/                 stack navigator + route types
  state/                      zustand store, types, real + mock scoring engines
  data/                       18-question bank
  theme/                      design tokens + font loader
  lib/                        supabase client + anonymous-auth bootstrap
assets/brand/                 ORVO logo + ensō mark (production assets)
supabase/                     schema.sql (tables, RLS, scoring function) + setup steps
```

## Running it

```
npm install
npm run start   # then choose iOS / Android / web
```

Backend setup (one-time, ~2 min): see `supabase/README.md`.

## What's a placeholder, and why

The design handoff is explicit that some things are **owned by ORVO Co.**
and must live server-side, not in the client. Most of that is now real (see
"Backend" below); what's still placeholder:

- **Question bank** (`src/data/questions.ts`) — dimensions 1–3 are final
  copy from the handoff. Dimensions 4–6 (Perception, Competitive standing,
  Internal alignment) are generic questions grounded in Interbrand's
  brand-strength factor definitions (Trust/Affinity, Presence/Participation,
  Direction/Alignment/Empathy/Agility) — not ORVO Co.-approved copy, and
  deliberately free of any specific client's survey content.
- **Legal identifiers** (`src/screens/LegalScreen.tsx`) — LLPIN, GSTIN,
  registered office and grievance officer are `[pending]` placeholders.
  These are legally required before release; see the `TODO(ORVO Co.)`
  comment in that file.
- **App icon / splash** — generated by compositing the ensō mark onto the
  canvas color (`#08090A`), since no dedicated icon existed. Fine as a
  placeholder; a real icon design should replace it before store submission.
- **Auth model** — anonymous sign-in only for now (no email/Google/Apple
  sign-in yet), and no PDF export / CRM routing.

## Backend

Real, on Supabase — see `supabase/README.md` for one-time setup and what's
real vs. still mocked. Short version: scoring weights, the dimension→suite
mapping and peer benchmarks (seeded synthetically per category, blended
toward real submitted scores as more audits come in) live in Postgres.
`src/state/scoring.ts` (the old client-side mock) is kept only as an
offline/network-failure fallback in `runScoringForAudit`
(`src/state/auditStore.ts`) — never blocks the user if Supabase is
unreachable.
